# Keep `mini-mas status` focused on Interactive Root Agent discovery

Status: ready-for-agent
Category: enhancement

## What to build

Keep `mini-mas status` as a lightweight Interactive Root Agent discovery command. Status and resume-validation paths should use read-only or control-plane access where feasible, avoid launching execution capacity, and avoid reporting AI Agent Execution activation state or queued AI Agent work.

## Acceptance criteria

- [ ] `mini-mas status` lists Interactive Root Agents only.
- [ ] `mini-mas status` does not report queued AI Agent work.
- [ ] `mini-mas status` does not report whether AI Agent Execution is active.
- [ ] The interactive prompt does not show a persistent AI Agent Execution indicator.
- [ ] Status and resume-validation paths avoid launching a DBOS executor when they only need metadata, where feasible behind a stable control-plane adapter.
- [ ] Tests prove status output remains focused on Interactive Root Agent discovery and excludes activation liveness and AI Agent queue state.

## Blocked by

- None - prerequisite issue is done.

> ## Agent Brief
>
> **Category:** enhancement
> **Summary:** Keep `mini-mas status` focused on Interactive Root Agent discovery and keep execution activation state out of status surfaces.
>
> **Current behavior:**
> `mini-mas status` is intended to be a lightweight External MAS CLI discovery command for Interactive Root Agents. Prior activation work split Interactive Agents and autonomous AI Agents onto separate DBOS queues, added explicit `mini-mas agent activate`, and proved staged AI Agent work executes only while activation is running.
>
> The remaining risk is that status-like inspection paths can drift into runtime dashboard behavior or unnecessarily launch execution capacity when they only need metadata. Status and resume-validation paths currently need careful boundaries so they do not report AI Agent Execution activation liveness, queued AI Agent work, or prompt-level activation indicators. They should prefer read-only or control-plane access behind a stable adapter where feasible.
>
> **Desired behavior:**
> `mini-mas status` should list Interactive Root Agents only. Its output should stay limited to Root discovery data such as Agent ID, lifecycle state, Agent Artifact Directory, and Trajectory Artifact path. It must not show queued AI Agent work, AI Agent queue state, AI Agent Execution activation liveness, or any runtime dashboard-style fields.
>
> Interactive terminal prompts should not show a persistent AI Agent Execution indicator. Activation state should remain runtime state communicated by the `mini-mas agent activate` startup notice, not an Agent lifecycle state, prompt concern, Child Status Event field, or `mini-mas status` concern.
>
> Status and resume-validation paths should avoid launching a DBOS executor when they only need metadata, where feasible through a stable read-only or control-plane adapter. If the current DBOS integration cannot fully support executor-free metadata reads, keep that limitation contained behind the adapter boundary, preserve explicit queue-listening policy, and do not expose activation or AI Agent queue state through status surfaces.
>
> **Key interfaces:**
> - External MAS CLI `status` command - should remain a Root discovery command and reject unsupported external governance lookup forms.
> - Interactive Root Agent discovery result - should contain only Interactive Root Agent discovery data and formatted output for those Roots.
> - Resume validation for an Interactive Root Agent - should validate target identity, parentlessness, workflow type, lifecycle availability, and attachment availability without becoming an execution activation or dashboard path.
> - Read-only or control-plane runtime adapter - should encapsulate metadata reads for workflow status and lifecycle event snapshots where feasible, so inspection paths have a stable boundary separate from execution-capable runtime launch.
> - AI Agent Execution activation notice - remains the place where activation liveness and side-effect risk are communicated at startup.
>
> **Acceptance criteria:**
> - [ ] `mini-mas status` lists Interactive Root Agents only.
> - [ ] `mini-mas status` output does not include Child Agent counts, Child Agent status, queued AI Agent work, AI Agent queue names, or AI Agent queue depth.
> - [ ] `mini-mas status` output does not report whether AI Agent Execution is active or inactive.
> - [ ] `mini-mas status` output does not include activation liveness, activation process state, runtime dashboard fields, or activation guidance beyond existing Root discovery/resume guidance.
> - [ ] Interactive terminal prompts do not show a persistent AI Agent Execution indicator.
> - [ ] Status discovery uses read-only or control-plane metadata access without launching a DBOS executor when feasible behind a stable adapter.
> - [ ] Resume validation uses read-only or control-plane metadata access without launching a DBOS executor when feasible behind the same or equivalent stable adapter.
