## Agent Brief

**Category:** enhancement
**Summary:** Queue spawned autonomous Child Agents as inactive AI Agent work.

**Current behavior:**
Spawned Child Agents are created through the existing MAS spawn path and currently use the legacy child workflow queue. Ordinary `mini-mas` runtime activation has already been constrained to Interactive Agent work, but spawned autonomous Child Agent work has not yet been aligned with the explicit AI Agent Execution boundary.

Detached Spawn and Waited Spawn allocate Child Agent metadata and enqueue Child Agent workflows from the Parent Agent context. The existing behavior preserves opaque Agent IDs, Parent Agent IDs, Agent Artifact Directories, Trajectory Artifact paths, and Direct Child Authority Policy.

**Desired behavior:**
Detached Spawn and Waited Spawn should enqueue autonomous Child Agents on `mini_mas_ai_agent_workflows`.

`mini-mas spawn "task"` should still enter through an Interactive Root Agent, submit the spawn command through that Root Agent, and return spawned Child Agent metadata. Creating or queuing Child Agent work must not require AI Agent Execution to be active.

Spawned Child Agents should remain durable queued AI Agent work until AI Agent Execution is explicitly activated. Queue placement must remain runtime/workflow infrastructure state; it must not be stored as Agent Metadata, exposed as a Child Status Event field, or represented by a new `queued` Agent lifecycle state.

Direct Child Authority Policy must remain unchanged: the Parent Agent that spawned the Child Agent keeps authority over its direct Child Agents, and activation must not grant broader authority.

**Key interfaces:**
- MAS queue catalog - `mini_mas_ai_agent_workflows` is the queue for autonomous AI Agent work.
- Spawn Agent Interaction - allocates Child Agent IDs, creates artifact metadata, and enqueues Child Agent workflows for Detached Spawn and Waited Spawn.
- Child Agent workflow startup - should be queued as AI Agent work without changing the Child Agent workflow's durable identity, parent relationship, artifact behavior, or lifecycle semantics.
- External one-shot spawn path - `mini-mas spawn "task"` creates or resumes the Interactive Root Agent path, submits the standalone spawn command through it, and returns Child Agent metadata without requiring active AI Agent Execution.
- Waited Spawn behavior - waits for First Observable Events from spawned Child Agents without introducing queue state as Agent lifecycle state.

**Acceptance criteria:**
- [x] Detached Spawn enqueues autonomous Child Agents on `mini_mas_ai_agent_workflows`.
- [x] Waited Spawn enqueues autonomous Child Agents on `mini_mas_ai_agent_workflows`.
- [x] The legacy child workflow queue is no longer used for newly spawned autonomous Child Agent work.
- [x] `mini-mas spawn "task"` can create or queue Child Agent work when AI Agent Execution is not active.
- [x] One-shot `mini-mas spawn "task"` still creates Child Agent work through the Interactive Root Agent path.
- [x] Spawned Child Agent metadata still includes the existing Agent ID, Parent Agent ID, Agent Artifact Directory, and Trajectory Artifact path behavior.
- [x] Queue placement is not added to Agent Metadata.
- [x] No `queued` Agent lifecycle state is introduced.
- [x] Direct Child Authority Policy is preserved for spawned Child Agents.
- [x] Tests prove AI Agent work spawned before activation is durable.
- [x] Tests prove ordinary `mini-mas` runtime activation does not consume spawned AI Agent work.
- [x] Tests cover both Detached Spawn and Waited Spawn.

**Out of scope:**
- Implementing `mini-mas agent activate`.
- Proving end-to-end consumption after activation starts; that belongs to the later staged execution issue.
- Reporting queued AI Agent work in `mini-mas status`.
- Reporting AI Agent Execution activation state in `mini-mas status`.
- Adding an Agent lifecycle state for queued work.
- Storing queue placement in Agent Metadata or Child Status Event data.
- Changing Direct Child Authority Policy.
- Adding broader Authority Grants for Descendant Agents or peers.
- Solving exactly-once side-effect recovery for model calls, bash actions, or spawn.
- Solving Workspace Isolation.
