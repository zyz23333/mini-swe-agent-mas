# Implement Waited Spawn and `mini-mas wait` synchronization

Status: ready-for-agent
Type: AFK

## Parent

.scratch/dbos-mas/PRD.md

## What to build

Implement synchronization commands for First Observable Events. `mini-mas spawn --wait` should start Child Agent Workflows and default to wait-any behavior, `mini-mas spawn --wait --timeout <seconds>` should bound only that waited-spawn wait phase, and `mini-mas wait` should let a Parent Agent Workflow wait for one workflow, all currently relevant workflows, any currently relevant workflow, or a bounded timeout.

The commands should return lightweight status and exact artifact paths, not full trajectory history.

## Acceptance criteria

- [ ] `mini-mas spawn "task A" "task B"` starts one Child Agent Workflow per repeated task argument.
- [ ] `mini-mas spawn --wait "task A" "task B"` defaults to wait-any behavior and returns when any started child sets a First Observable Event.
- [ ] `mini-mas spawn --wait --all "task A" "task B"` waits until all started children set First Observable Events.
- [ ] `mini-mas spawn --wait --timeout <seconds> "task A" "task B"` returns timeout information when no started child sets a First Observable Event before the deadline.
- [ ] `mini-mas spawn --wait --all --timeout <seconds> "task A" "task B"` returns partial ready snapshots and still-running child IDs when not all children become observable before the deadline.
- [ ] Waited Spawn timeout does not cancel, close, fail, retry, or otherwise stop started Child Agent Workflows.
- [ ] `mini-mas spawn --timeout <seconds> "task"` without `--wait` is rejected as invalid because Detached Spawn has no wait phase.
- [ ] Detached multi-spawn returns all started child workflow IDs, Run Directory, and exact Trajectory Artifact paths without waiting.
- [ ] Waited multi-spawn returns all started child metadata plus ready child snapshots and still-running child IDs.
- [ ] `mini-mas wait <workflow-id>` waits for a specific descendant First Observable Event.
- [ ] `mini-mas wait --all` gathers all currently relevant child First Observable Events.
- [ ] `mini-mas wait --any` returns when any currently relevant child sets a First Observable Event.
- [ ] `mini-mas wait --timeout <seconds>` returns bounded timeout information when children are still running.
- [ ] Waited Spawn and `mini-mas wait` wait on child DBOS events keyed by child workflow identifiers, not on `WorkflowHandle.get_result()` or final DBOS workflow completion.
- [ ] Child-to-parent observable state uses DBOS events; parent-to-child Continuation Signals and Close Signals remain DBOS messages.
- [ ] Wait results include workflow IDs, lifecycle states, latest submission or error when present, Run Directory, and exact Trajectory Artifact paths.
- [ ] Tests cover single-child and multi-child spawn, detached multi-spawn, waited spawn default wait-any, waited spawn `--all`, waited spawn wait-any timeout, waited spawn wait-all partial timeout, invalid detached spawn timeout, wait for one, `--all`, `--any`, timeout behavior, and no dedicated history/log output.

## Agent Brief

**Category:** enhancement
**Summary:** Implement Waited Spawn and `mini-mas wait` synchronization on First Observable Events.

**Current behavior:**
The MAS subsystem can start Root Agent Workflows, start a single Child Agent Workflow through Detached Spawn, expose lightweight Child Status Events through `mini-mas status`, and publish a child's First Observable Event when the child first reaches a parent-actionable state such as `waiting_for_parent`, `failed`, or `limits_exceeded`.

`mini-mas spawn` currently covers only the existing detached child-start path. It does not yet support repeated task arguments as a single multi-spawn command, waited-spawn synchronization, waited-spawn timeout behavior, or the user-facing `mini-mas wait` command. Parent Agent Workflows therefore cannot yet synchronize on First Observable Events except indirectly through status inspection.

The previous blocker, `.scratch/dbos-mas/issues/08-make-child-workflows-wait-after-first-submission.md`, is complete. Child Agent Workflows now publish First Observable Events and wait for parent direction after first submission, so this issue can build on that behavior.

**Desired behavior:**
`mini-mas spawn` should accept one or more repeated task arguments and start one Child Agent Workflow per task. Without `--wait`, it should remain a Detached Spawn and return immediately with metadata for every started child.

`mini-mas spawn --wait` should request Waited Spawn. Waited Spawn should still start all requested children, then wait for First Observable Events from those children. By default it should use wait-any behavior and return when any started child becomes observable. With `--all`, it should wait until all started children become observable. With `--timeout <seconds>`, the timeout should bound only the wait phase and must not cancel, close, fail, retry, or otherwise stop started Child Agent Workflows.

`mini-mas wait` should let a Parent Agent Workflow synchronize on First Observable Events for currently relevant children. It should support waiting for one explicit descendant workflow ID, waiting for any currently relevant child with `--any`, waiting for all currently relevant children with `--all`, and bounded timeout behavior with `--timeout <seconds>`.

Waited Spawn and `mini-mas wait` must synchronize on child-keyed DBOS First Observable Events. They must not wait on `WorkflowHandle.get_result()` or final DBOS workflow completion. Child-to-parent observable state should remain DBOS event based. Parent-to-child Continuation Signals and Close Signals remain DBOS workflow messages and are not part of this issue's implementation.

Command results should be lightweight coordination summaries. They should include workflow IDs, lifecycle states, latest submission or latest error when present, Run Directory, and exact Trajectory Artifact paths. They should not include full trajectory history.

**Key interfaces:**
- `mini-mas spawn` MAS Command - should parse repeated task arguments, `--wait`, `--all`, and `--timeout <seconds>` while preserving Detached Spawn as the default.
- `mini-mas wait` MAS Command - should support explicit workflow ID waiting, `--all`, `--any`, and `--timeout <seconds>` inside a Parent Agent Workflow.
- External MAS CLI `wait` command - should expose equivalent status/wait behavior for workflow IDs where appropriate for the current MAS CLI boundary.
- Child Agent Workflow startup - should start one Child Agent Workflow per task and return deterministic Workflow Tree IDs and artifact metadata for each child.
- First Observable Event lookup - should wait on child workflow identifiers and return the event payloads published by Child Agent Workflows.
- Wait result shape - should expose ready child snapshots, still-running child IDs on partial timeout, lifecycle state, latest submission or error, Run Directory, and exact Trajectory Artifact path.
- MAS command validation - should reject `mini-mas spawn --timeout <seconds> "task"` when `--wait` is absent because Detached Spawn has no wait phase.
- Observation formatting path - should keep using existing model adapter observation formatting for MAS command outputs.
