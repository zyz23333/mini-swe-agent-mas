# Support Detached Spawn with deterministic Child Agent Workflow IDs

Status: ready-for-agent
Type: AFK

## Parent

.scratch/dbos-mas/PRD.md

## What to build

Implement `mini-mas spawn "task"` inside a Parent Agent Workflow as a Detached Spawn. The command should start a Child Agent Workflow through the child workflow queue, return immediately to the parent with child identifiers and artifact paths, and use deterministic Workflow Tree IDs so DBOS recovery does not create duplicate descendants.

This slice should make one parent-to-child delegation path work end to end without waiting for the child submission.

## Acceptance criteria

- [ ] A Parent Agent Workflow can emit `mini-mas spawn "task"` as a Standalone MAS Command.
- [ ] Detached Spawn starts a Child Agent Workflow through a DBOS queue for child-agent concurrency control.
- [ ] The command returns immediately with child Workflow Tree ID, Run Directory, and Trajectory Artifact path.
- [ ] Child Workflow Tree IDs append deterministic `-cNNN` segments to the parent workflow ID.
- [ ] Replaying or recovering the parent spawn path does not create duplicate child workflow IDs for the same logical spawn.
- [ ] The child belongs to the same Run Directory as the Root Agent Workflow.
- [ ] Tests cover detached spawn output, queue usage, deterministic child IDs, and artifact path visibility.

## Agent Brief

**Category:** enhancement
**Summary:** Implement Detached Spawn so a Parent Agent Workflow can start a Child Agent Workflow with deterministic child Workflow Tree IDs and immediately receive child artifact metadata.

**Current behavior:**
The MAS subsystem can start a Root Agent Workflow, persist deterministic Run Directory and Trajectory Artifact paths, classify Standalone MAS Commands, and keep MAS command dispatch at the Agent Workflow layer. Ordinary model and bash work is checkpointed through DBOS steps, while Standalone MAS Commands are routed away from ordinary bash execution.

The `mini-mas spawn "task"` command is not implemented as real child coordination yet. Accepted MAS commands currently do not start a Child Agent Workflow, do not use a child workflow queue, and do not return child Workflow Tree ID or child Trajectory Artifact metadata.

**Desired behavior:**
A Parent Agent Workflow should be able to emit `mini-mas spawn "task"` as a Standalone MAS Command. The command should be handled through MAS Command Interception at the workflow layer, start exactly one Child Agent Workflow through the child workflow queue, and return immediately to the parent without waiting for the child's submission or terminal state.

The Detached Spawn result should be formatted as a normal command observation for the parent and should include the child Workflow Tree ID, the shared Run Directory, and the exact child Trajectory Artifact path. The child must belong to the same Root Agent Workflow run as the parent, so its Trajectory Artifact is written under the same Run Directory as the root.

Child Workflow Tree IDs must be deterministic for a logical spawn. First-level child IDs append `-cNNN` to the parent Workflow Tree ID, starting at `-c001` and incrementing for sibling spawns. Recovery or replay of the same parent spawn path must reuse the same child Workflow Tree ID for the same logical spawn instead of creating an additional descendant. This is required so DBOS recovery does not duplicate children.

Workflow-control operations for spawning and queueing children must remain outside DBOS step functions. The child workflow itself can reuse the existing Agent Workflow behavior where appropriate, but Detached Spawn must not route child creation through ordinary bash execution.

**Key interfaces:**
- Standalone MAS Command dispatch - should parse and execute `spawn` as a workflow-layer MAS command, while preserving existing rejection behavior for non-standalone shell compositions.
- Child Agent Workflow - should represent one delegated Agent Workflow and receive enough input to run the delegated task in the same Root Agent Workflow context.
- Workflow Tree ID allocation - should generate deterministic `-cNNN` child segments from the Parent Agent Workflow ID and the logical spawn position.
- Child workflow queue - should enqueue Child Agent Workflows for global child-agent concurrency control rather than starting them through ordinary bash or unqueued direct calls.
- Spawn command result shape - should expose child Workflow Tree ID, Run Directory, and Trajectory Artifact path in the parent-visible observation.
- Trajectory Artifact metadata - should support child artifact paths under the Root Agent Workflow Run Directory.

**Acceptance criteria:**
- [ ] A Parent Agent Workflow can emit `mini-mas spawn "task"` as a Standalone MAS Command and have it handled at the workflow layer.
- [ ] Detached Spawn starts one Child Agent Workflow through a DBOS child workflow queue.
- [ ] Detached Spawn returns immediately to the Parent Agent Workflow without waiting for the child's first submission or terminal state.
- [ ] The parent-visible command observation includes the child Workflow Tree ID, shared Run Directory, and exact child Trajectory Artifact path.
- [ ] First-level Child Agent Workflow IDs append deterministic `-cNNN` segments to the Parent Agent Workflow ID, for example `mas-<16hex>-c001`.
- [ ] Multiple sibling spawns from the same parent receive stable incrementing IDs such as `-c001`, `-c002`, and `-c003`.
- [ ] Recovery or replay of the same logical spawn path reuses the same child Workflow Tree ID and does not create duplicate child descendants.
- [ ] The child Trajectory Artifact is written under the same Root Agent Workflow Run Directory as the parent.
- [ ] Standalone MAS command parsing and rejection behavior for non-standalone shell compositions remains unchanged.
- [ ] Tests cover detached spawn output, child queue usage, deterministic child ID generation, replay or recovery duplicate prevention, and child artifact path visibility.

**Out of scope:**
- Implementing `mini-mas spawn --wait` or any Waited Spawn behavior.
- Implementing `mini-mas wait`, `continue`, or `close`.
- Implementing full `mini-mas status` tree inspection beyond whatever minimal internal child metadata is needed for Detached Spawn.
- Implementing Remote Interactive Agent waiting after first submission, Continuation Signals, or Close Signals.
- Implementing recursive grandchild coordination beyond preserving a Workflow Tree ID scheme that can support it later.
- Solving Shared Workspace isolation or exactly-once semantics for arbitrary bash side effects.
