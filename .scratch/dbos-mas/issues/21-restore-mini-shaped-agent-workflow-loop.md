## Refactor map reference

This issue must follow `.scratch/dbos-mas/issues/16-record-mas-deep-module-refactor-map.md` and any design note produced from it. Preserve the module boundaries, DBOS step/workflow-control boundaries, and out-of-scope constraints recorded there; do not invent alternate MAS module names, authority models, DBOS behavior, or command fallbacks.

## What to build

Refactor the **Agent Workflow** runner so its external shape resembles mini-swe-agent's core loop: query model, execute bash-shaped actions with **MAS Command Interception**, append model-specific observations, stop on terminal exit, and save the trajectory. DBOS-specific complexity, command dispatch, status publication, and child lifecycle behavior should sit behind deeper **Modules** and **Adapters**.

This slice should keep `root_agent_workflow` and `child_agent_workflow` as thin async DBOS workflow entrypoints.

## Acceptance criteria

- [ ] `root_agent_workflow` and `child_agent_workflow` remain async DBOS workflows.
- [ ] The core **Agent Workflow** loop has a small **Interface** and does not inline MAS command dispatch internals.
- [ ] Model query still runs through `query_model_step`.
- [ ] Ordinary bash execution still runs through `execute_bash_step`.
- [ ] Trajectory persistence still runs through DBOS steps.
- [ ] Limits exceeded behavior and terminal result behavior remain compatible.
- [ ] Existing workflow registration, step registration, trajectory artifact, ordinary bash, and observation formatting tests pass.

> ## Agent Brief

> **Category:** enhancement
> **Summary:** Refactor the MAS Agent Workflow runner so its top-level shape reads like mini-swe-agent's core agent loop while preserving existing MAS behavior.
>
> **Current behavior:**
> The MAS Agent Workflow implementation already preserves the required runtime behavior: model queries go through the DBOS model step, ordinary bash goes through the DBOS bash step, Standalone MAS Commands are intercepted at the Agent Workflow layer, trajectory artifacts are persisted through DBOS steps, and child coordination uses the existing MAS command handler, Direct Child Authority Policy, and DBOS Coordination Adapter.
>
> However, the top-level Agent Workflow module still mixes several concerns in one place: workflow entrypoints, mutable loop state, model query orchestration, action execution, status publication wrappers, parent-direction signal construction and recognition, child waiting behavior, terminal result handling, and trajectory persistence calls. The resulting shape is harder to compare with mini-swe-agent's small agent loop.
>
> **Desired behavior:**
> The Root Agent Workflow and Child Agent Workflow entrypoints should remain async DBOS workflows, but should delegate ordinary per-workflow orchestration to a plain `MasAgent`-style object whose public surface resembles mini-swe-agent's core loop: `run`, `step`, `query`, `execute_actions`, `add_messages`, and `get_template_vars`.
>
> The Agent Workflow loop should read as:
>
> - query the model through the existing DBOS model-query step;
> - execute bash-shaped actions through MAS-aware action execution;
> - route Standalone MAS Commands through the existing command handling boundary;
> - route ordinary bash through the existing DBOS bash execution step;
> - format and append model-specific observations;
> - stop on terminal exit or limits exceeded;
> - persist the trajectory through existing DBOS trajectory steps.
>
> DBOS-specific coordination, command dispatch details, direct-child authority validation, status/event waiting, and parent-direction signal delivery should remain behind the existing deep modules and adapters. This refactor must preserve current model-visible behavior.
>
> **Key interfaces:**
> - `root_agent_workflow` - remains an async module-level DBOS workflow entrypoint.
> - `child_agent_workflow` - remains an async module-level DBOS workflow entrypoint.
> - `query_model_step` - remains the DBOS step wrapper for model calls.
> - `execute_bash_step` - remains the DBOS step wrapper for ordinary bash execution.
> - trajectory persistence step wrappers - remain DBOS steps and continue writing the same trajectory artifact shape.
> - MAS command classification and command dispatch interfaces - continue to decide Standalone MAS Command interception and model-facing command results.
> - DBOS Coordination Adapter - remains the boundary for DBOS workflow-control primitives used by Agent Workflow code.
> - Direct Child Authority Policy - remains the fixed MVP authority model.
>
