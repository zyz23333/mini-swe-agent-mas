## What to build

Create a result formatting **Module** for model-visible MAS command results. `status`, `spawn`, `wait`, `continue`, and `close` should return consistent `output`, `returncode`, `exception_info`, and `extra` shapes without each command branch manually constructing strings and dictionaries in place.

The formatting **Module** should preserve existing output compatibility while making the output shape a single testable **Interface**.

## Acceptance criteria

- [x] `status` output still includes direct child workflow ID, lifecycle state, latest submission or error when present, run directory, and trajectory artifact path.
- [x] `spawn` output still includes started child metadata and waited-spawn summaries.
- [x] `wait` output still includes wait mode, ready children, still-running child workflow IDs, run directory, and trajectory artifact paths.
- [x] `continue` and `close` outputs still include target workflow metadata and signal result details.
- [x] Error results still include stable return code, exception info, and `mas_command_error` extras.
- [x] Existing CLI and workflow command output tests pass.

> **Category:** enhancement
> **Summary:** Consolidate model-visible MAS command result formatting behind one testable interface.
>
> **Current behavior:**
> Workflow-layer MAS command dispatch already receives classified Standalone MAS Commands, delegates spawn and wait coordination to child coordination behavior, and preserves the existing model-facing observation dictionary shape. However, command result construction is still scattered across command-specific branches and adjacent helper paths. Success and error results each manually assemble combinations of `output`, `returncode`, `exception_info`, and `extra`, which makes output compatibility harder to audit and makes future command changes likely to duplicate formatting logic.
>
> The affected behavior includes model-visible results for `status`, `spawn`, `wait`, `continue`, and `close`, plus command argument errors, missing Agent Workflow context errors, Direct Child Authority Policy errors, and external/operator coordination errors where they share the same result contract.
>
> **Desired behavior:**
> Introduce or deepen a MAS command result formatting Module that owns the model-visible command result contract. Command handling code should pass structured command/domain data into this interface and receive a stable observation result dictionary containing:
>
> - `output`
> - `returncode`
> - `exception_info`
> - `extra`
>
> The formatting interface must preserve the existing user/model-visible output content. This is a behavior-preserving refactor: the goal is to make formatting a single testable interface, not to redesign command syntax, command routing, authority policy, DBOS coordination behavior, lifecycle states, or artifact metadata.
>
> Command branches should remain responsible for parsing Standalone MAS Command arguments and invoking the correct domain behavior. Coordination modules should continue returning structured MAS domain results rather than model-facing observation dictionaries. Direct Child Authority Policy should remain the only authority path for explicit child targets.
>
> Error results should continue to expose stable return codes, stable `exception_info` values, and `mas_command_error` extras. Success results should continue to include the same command-specific extras needed by existing workflow behavior, including child workflow identifiers, child metadata, waited-spawn and wait summaries, ready child snapshots, still-running child workflow IDs, target status snapshots, and signal details.
>
> **Key interfaces:**
> - MAS command result formatting interface - owns conversion from structured command/domain data into the model-visible observation result dictionary shape.
> - `MasCommandHandler` - should keep dispatching already-classified Standalone MAS Commands while delegating common result construction to the formatting interface.
> - Child coordination result types - should remain structured domain results for spawn and wait behavior, not model-facing observation dictionaries.
> - Direct Child Authority Policy result types - should remain structured policy results or errors whose model-visible representation is produced consistently through the formatting interface.
> - Parent-direction signal senders - should preserve continuation and close signal behavior while aligning their returned command result shape with the shared formatting path.
>
