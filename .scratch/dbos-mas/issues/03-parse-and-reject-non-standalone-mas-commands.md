# Parse and reject non-standalone MAS Commands

Status: ready-for-agent
Type: AFK

## Parent

.scratch/dbos-mas/PRD.md

## What to build

Teach the Agent Workflow execution path to distinguish Standalone MAS Commands from ordinary bash commands while preserving mini-swe-agent's existing bash-shaped model action contract. A command beginning with `mini-mas` should be intercepted only when the full action command is a valid Standalone MAS Command. Shell compositions that contain `mini-mas` must produce a clear corrective error instead of being partially intercepted or executed as ambiguous bash.

This slice should prove command parsing and observation formatting end to end with deterministic model outputs, without implementing the full coordination command set yet.

## Acceptance criteria

- [ ] Standalone MAS Commands are detected only when `mini-mas ...` occupies the whole action command.
- [ ] Ordinary bash commands that do not invoke `mini-mas` continue through ordinary bash execution.
- [ ] Shell operators, environment assignments, loops, pipes, redirections, and embedded `mini-mas` fragments are rejected for MAS interception with a clear error.
- [ ] Model adapters still produce bash-shaped actions with a `command` string; no separate `mini-mas` model tool schema is introduced.
- [ ] Observation formatting remains model-specific and uses existing text-based, toolcall, and Responses API patterns.
- [ ] Tests cover accepted standalone commands and rejected shell-composition cases.

## Agent Brief

**Category:** enhancement
**Summary:** Parse Agent Workflow actions so only Standalone MAS Commands are intercepted, while shell compositions containing `mini-mas` are rejected with a corrective observation.

**Current behavior:**
The MAS subsystem has an isolated External MAS CLI and a minimal Root Agent Workflow with deterministic artifact paths. The model action contract is still bash-shaped: model adapters produce actions containing a `command` string. The MAS Agent Workflow execution path does not yet distinguish Standalone MAS Commands from ordinary bash commands before execution.

As a result, there is not yet a durable boundary that says whether an action command should be handled by workflow-layer MAS dispatch, ordinary bash execution, or a corrective rejection when `mini-mas` appears inside a shell composition.

**Desired behavior:**
Inside an Agent Workflow, every model action should keep the existing bash-shaped action contract and be classified before execution.

A command should be treated as a Standalone MAS Command only when `mini-mas ...` occupies the whole action command. Valid standalone commands should be routed to workflow-layer MAS dispatch. For this slice, the command dispatcher can be minimal or stubbed for not-yet-implemented MAS coordination commands, as long as the parsing, routing, and observation behavior are proven end to end.

Ordinary bash commands that do not invoke `mini-mas` should continue through ordinary bash execution.

Commands that contain `mini-mas` as part of a shell composition should not be partially intercepted and should not be executed as ambiguous bash. They should produce a clear corrective error observation telling the model to issue `mini-mas` as a standalone command. Rejected cases include shell operators, environment assignments, loops, pipes, redirections, command substitutions, and embedded `mini-mas` fragments.

Model adapters must continue to produce normal bash-shaped actions with a `command` string. This work must not introduce a separate `mini-mas` model tool schema and must not modify model-side action parsers.

Observation formatting should continue to use the existing model-specific mechanisms for text-based models, chat tool calls, and Responses API tool calls.

**Key interfaces:**
- Model action shape - actions remain dictionaries with a `command` string, plus any existing model-specific metadata such as tool call IDs.
- Agent Workflow action execution - should classify actions before deciding whether to dispatch MAS coordination, execute ordinary bash, or return a corrective rejection.
- MAS command parser/classifier - should distinguish standalone `mini-mas ...`, ordinary bash, and invalid shell compositions containing `mini-mas`.
- Workflow-layer MAS dispatcher - receives only validated Standalone MAS Commands.
- Ordinary bash execution path - receives commands that do not invoke `mini-mas`.
- Observation formatting - existing text-based, toolcall, and Responses API formatting paths should receive outputs in the shape they already understand.

**Acceptance criteria:**
- [ ] A command where `mini-mas ...` occupies the whole action command is detected as a Standalone MAS Command.
- [ ] Valid Standalone MAS Commands are routed to workflow-layer MAS dispatch rather than ordinary bash execution.
- [ ] Ordinary bash commands that do not invoke `mini-mas` continue through ordinary bash execution.
- [ ] Commands containing `mini-mas` inside shell compositions are rejected with a clear corrective error rather than partially intercepted.
- [ ] Rejected shell composition cases include shell operators, environment assignments, loops, pipes, redirections, and embedded `mini-mas` fragments.
- [ ] Model adapters still produce bash-shaped actions with a `command` string.
- [ ] No separate `mini-mas` model tool schema is introduced.
- [ ] Observation formatting remains compatible with existing text-based model, chat toolcall, and Responses API patterns.
- [ ] Tests cover accepted standalone commands.
- [ ] Tests cover rejected shell-composition cases.
- [ ] Tests cover ordinary bash pass-through.
- [ ] Tests use deterministic model outputs and avoid real LLM calls.

**Out of scope:**
- Implementing full `mini-mas spawn`, `status`, `wait`, `continue`, or `close` behavior.
- Implementing Child Agent Workflow lifecycle, child queues, status events, continuation signals, or close signals.
- Moving MAS command handling into environment implementations.
- Converting `DefaultAgent` or `InteractiveAgent` into DBOS workflows.
- Changing model-side action parsers or adding a dedicated model tool schema for `mini-mas`.
- Claiming Workspace Isolation or exactly-once bash side-effect semantics.
