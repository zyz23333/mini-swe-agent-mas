# Simplify MAS module boundaries

Status: ready-for-agent
Category: enhancement
Type: AFK

## Parent

.scratch/dbos-mas/PRD.md

## What to build

Simplify the DBOS-backed MAS implementation by collapsing small single-use modules and duplicate step wrappers back into clearer local code. This is a behavior-preserving KISS refactor: the Agent Workflow loop, DBOS workflow-control boundaries, Direct Child Authority Policy semantics, Child Status Events, First Observable Events, Continuation Signals, Close Signals, model-visible command output, workflow IDs, artifact paths, and CLI behavior must remain compatible.

The refactor should make the MAS implementation easier to read by reducing indirection in three places:

1. Inline `remote_lifecycle.py` back into `MasAgent` as straightforward private methods for submitted-child waiting, continuation, and neutral close handling.
2. Merge the separate root and child trajectory persistence step wrappers into one DBOS step that accepts both `root_workflow_id` and `workflow_id`.
3. Consolidate MAS command handling into one command module so command parsing, dispatch, direct-child authorization, and model-visible result construction are no longer spread across several tiny modules.

## Notes

This issue intentionally changes the refactor direction from the earlier deep-module extraction work. The goal is not to remove DBOS durability boundaries or weaken MAS semantics; it is to reduce single-use indirection where the current code reads like a framework instead of a small Agent Workflow implementation.

Keep the final structure boring and local:

- `mas_agent.py` owns the readable Agent Workflow loop and DBOS workflow/step entrypoints.
- One command module owns Standalone MAS Command parsing, dispatch, direct-child checks, and result dictionaries.
- `coordination.py`, `status_events.py`, `signals.py`, and `artifacts.py` stay only where they still remove real complexity.

Out of scope:

- Changing MAS command syntax.
- Removing any supported `mini-mas` subcommand.
- Changing wait semantics, First Observable Event semantics, or Child Status Event shapes.
- Introducing broader authority scopes, Authority Grants, subtree-wide authority, Root Agent Workflow tree-wide authority, or external operator authority.
- Moving model calls, ordinary bash execution, or trajectory persistence out of DBOS steps.
- Adding Workspace Isolation, Operation Ledger behavior, cancellation, retries, or new DBOS behavior.
