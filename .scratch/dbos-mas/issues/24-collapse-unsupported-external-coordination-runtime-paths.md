## Agent Brief

**Category:** enhancement
**Summary:** Collapse duplicated unsupported External MAS CLI coordination runtime paths into one shared unsupported-response path.

**Current behavior:**
External `mini-mas status`, `mini-mas wait`, `mini-mas continue`, and `mini-mas close` are intentionally unsupported until terminal commands are routed through an **Interactive Root Agent Workflow**. Each runtime path currently returns the same unsupported coordination response independently. These unsupported external coordination commands must not configure DBOS, launch DBOS, inspect DBOS workflows, send DBOS messages, or introduce external operator authority.

`mini-mas run` is the supported external startup path. It configures DBOS, launches DBOS, and starts a **Root Agent Workflow** through async DBOS workflow startup.

**Desired behavior:**
The unsupported external coordination response for `status`, `wait`, `continue`, and `close` should be generated through one shared runtime path while preserving the existing user-visible unsupported behavior. The shared path should keep the same return shape and error meaning used by the current unsupported external coordination commands.

The refactor must preserve the MAS architecture constraints recorded in the PRD and MAS deep module refactor map: do not invent external operator authority, broader **Coordination Authority Models**, DBOS behavior, command fallbacks, or alternate MAS module boundaries.

**Key interfaces:**
- External MAS runtime functions for `status`, `wait`, `continue`, and `close` — these should continue to return unsupported external coordination results with `external_coordination_unsupported` semantics.
- External MAS runtime startup for `run` — this remains the only external command path that configures DBOS, launches DBOS, and starts `root_agent_workflow`.
- External MAS CLI commands for `status`, `wait`, `continue`, and `close` — these should continue to print the unsupported response and exit with the unsupported return code.

**Acceptance criteria:**
- [ ] External `mini-mas status` still reports unsupported external coordination behavior.
- [ ] External `mini-mas wait` still reports unsupported external coordination behavior.
- [ ] External `mini-mas continue` still reports unsupported external coordination behavior.
- [ ] External `mini-mas close` still reports unsupported external coordination behavior.
- [ ] Unsupported external coordination commands do not configure DBOS, launch DBOS, inspect DBOS workflows, or send DBOS messages.
- [ ] `mini-mas run` continues to configure DBOS, launch DBOS, and start `root_agent_workflow` through async DBOS workflow startup.
- [ ] Existing runtime and CLI tests pass.

**Out of scope:**
- Implementing naked external/operator `status`, `wait`, `continue`, or `close` coordination APIs.
- Implementing the **Interactive Root Agent Workflow** terminal command path.
- Adding external operator authority, tree-wide authority, subtree-wide authority, or **Authority Grants**.
- Changing workflow-layer MAS Command behavior inside an **Agent Workflow**.
- Changing `mini-mas run` startup behavior beyond preserving existing behavior.
