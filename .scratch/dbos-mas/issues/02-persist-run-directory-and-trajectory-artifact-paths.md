## What to build

Make `mini-mas run` create deterministic artifact locations for a Root Agent Workflow. Every MAS run should have a Run Directory scoped by the Root Workflow Tree ID, and the Root Agent Workflow should write a Trajectory Artifact to a deterministic path that can be returned to users and inspected with ordinary shell tools.

This slice should make artifact creation visible through the External MAS CLI without introducing history, logs, grep, diff, or inspector commands.

## Agent Brief

**Category:** enhancement
**Summary:** Persist deterministic Run Directory and Trajectory Artifact paths for `mini-mas run`.

**Current behavior:**
The External MAS CLI already has a minimal `mini-mas run` path that initializes and launches DBOS only through the MAS subsystem, starts a minimal Root Agent Workflow, and returns a workflow identifier. Root Workflow Tree IDs are generated in the `mas-<16hex>` shape, but the run does not yet expose a Run Directory, does not persist a Trajectory Artifact under that directory, and does not print artifact paths for ordinary shell inspection.

The existing single-agent trajectory save behavior creates parent directories and overwrites the target JSON file when saving to the same path. The MAS slice should preserve ordinary `mini` behavior and should keep artifact semantics inside the MAS subsystem boundary.

**Desired behavior:**
Every `mini-mas run` invocation should create deterministic artifact locations for the Root Agent Workflow. The Root Workflow Tree ID should identify the Run Directory, and the Root Agent Workflow should write a Trajectory Artifact to a deterministic JSON path under that directory.

The Run Directory must be `.mini-mas/runs/<root-workflow-id>/`. The Root Agent Workflow's Trajectory Artifact must be `.mini-mas/runs/<root-workflow-id>/trajectories/<workflow-id>.traj.json`. For the root workflow in this slice, the root workflow ID and workflow ID are expected to be the same unless the implementation deliberately distinguishes those concepts while preserving the path contract.

Repeated trajectory saves for the same workflow should resolve to the same path and overwrite safely. The External MAS CLI output should include the Root Workflow Tree ID, the Run Directory, and the exact Trajectory Artifact path so users and parent workflows can inspect artifacts with ordinary shell tools.

**Key interfaces:**
- Root Workflow Tree ID generation - root IDs must keep the `mas-<16hex>` form.
- Run Directory path generation - derives `.mini-mas/runs/<root-workflow-id>/` from the Root Workflow Tree ID.
- Trajectory Artifact path generation - derives `.mini-mas/runs/<root-workflow-id>/trajectories/<workflow-id>.traj.json` from the Run Directory and Agent Workflow ID.
- Root Agent Workflow result or metadata - should carry enough artifact information for `mini-mas run` to print the Root Workflow Tree ID, Run Directory, and Trajectory Artifact path.
- External MAS CLI output - should expose the exact values, not just a generic workflow result.
- Trajectory persistence - should create needed directories and overwrite the same file path for repeated saves of the same workflow.

**Acceptance criteria:**
- [x] Root Workflow Tree IDs generated for `mini-mas run` match `mas-<16 lowercase hex characters>`.
- [x] `mini-mas run` creates a Run Directory at `.mini-mas/runs/<root-workflow-id>/`.
- [x] The Root Agent Workflow writes a Trajectory Artifact at `.mini-mas/runs/<root-workflow-id>/trajectories/<workflow-id>.traj.json`.
- [x] Repeated saves for the same workflow resolve to the same Trajectory Artifact path and overwrite the artifact without creating duplicate files.
- [x] CLI output includes the Root Workflow Tree ID, Run Directory, and exact Trajectory Artifact path.
- [x] Tests cover root ID shape, Run Directory path generation, Trajectory Artifact path generation, repeated-save overwrite behavior, and CLI-visible output.
- [x] Existing ordinary `mini` CLI behavior remains outside DBOS runtime activation and is not changed by this slice.

**Out of scope:**
- Implementing `mini-mas spawn`, `status`, `wait`, `continue`, or `close`.
- Implementing Child Agent Workflows, descendant Workflow Tree IDs, or recursive coordination.
- Implementing Standalone MAS Command interception.
- Adding dedicated history, logs, grep, diff, or inspector commands for MAS artifacts.
- Changing the ordinary `mini` default output path or single-agent trajectory format.
- Solving Workspace Isolation, Operation Ledger behavior, or exactly-once side-effect recovery.
