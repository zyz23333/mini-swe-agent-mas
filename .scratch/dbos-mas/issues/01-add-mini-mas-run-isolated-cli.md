## Agent Brief

**Category:** enhancement
**Summary:** Add an isolated `mini-mas run` External MAS CLI that starts a minimal Root Agent Workflow through DBOS without changing ordinary `mini` behavior.

**Current behavior:**
The project exposes the existing `mini`, `mini-swe-agent`, `mini-extra`, and `mini-e` entrypoints. There is no `mini-mas` External MAS CLI, no MAS-specific DBOS launch path, and no Root Agent Workflow startup path. Ordinary `mini` invocations construct the existing model, environment, and agent path directly and should remain non-DBOS.

**Desired behavior:**
The project should expose a separate `mini-mas` script with a minimal `run` command. Running `mini-mas run` should initialize and launch DBOS only through the MAS path, start a minimal Root Agent Workflow, and return a clear workflow identifier or result. The existing `mini` command and its related scripts should remain operationally unchanged and should not configure, launch, or otherwise activate DBOS during ordinary single-agent use.

The MAS implementation must live behind a separate subsystem boundary. This first slice only needs to prove the end-to-end boundary: DBOS as a default dependency, script entrypoint, MAS-only DBOS launch path, minimal Root Agent Workflow startup, and regression coverage that ordinary `mini` remains isolated from DBOS runtime activation.

**Key interfaces:**
- Project dependencies - DBOS should be installed as a default dependency for this MAS branch, not hidden behind an optional extra.
- Project console scripts - `mini-mas` should be added without changing the existing `mini`, `mini-swe-agent`, `mini-extra`, or `mini-e` script targets.
- External MAS CLI - should provide a minimal `run` command that is responsible for entering the MAS path.
- Root Agent Workflow - should be represented as a DBOS workflow and should be startable through `mini-mas run`.
- Existing ordinary CLI path - ordinary `mini` invocation should continue using the existing single-agent path and should not initialize or launch DBOS.
- MAS subsystem boundary - the implementation should not convert `DefaultAgent` or `InteractiveAgent` into DBOS workflows.

**Acceptance criteria:**
- [x] DBOS is installed as a default project dependency for this branch.
- [x] The project exposes a `mini-mas` console script.
- [x] Adding `mini-mas` does not change the existing `mini`, `mini-swe-agent`, `mini-extra`, or `mini-e` console script targets.
- [x] `mini-mas run` initializes and launches DBOS through the MAS path.
- [x] `mini-mas run` starts a minimal Root Agent Workflow.
- [x] `mini-mas run` returns a clear workflow identifier or workflow result.
- [x] Existing `mini` CLI tests still pass.
- [x] Tests cover that ordinary `mini` invocation does not initialize or launch DBOS.
- [x] The MAS implementation is separated from the existing default and interactive agent classes.
- [x] `DefaultAgent` and `InteractiveAgent` are not converted into DBOS workflows.

**Out of scope:**
- Implementing `mini-mas spawn`, `status`, `wait`, `continue`, or `close`.
- Implementing Child Agent Workflows, Remote Interactive Agent lifecycle, Continuation Signals, or Close Signals.
- Implementing Standalone MAS Command interception inside an Agent Workflow.
- Persisting final Run Directory and Trajectory Artifact path semantics beyond what is minimally needed for this first `run` slice.
- Workspace Isolation, Operation Ledger behavior, or exactly-once side-effect guarantees.
- Adding a separate model tool schema for `mini-mas`.
