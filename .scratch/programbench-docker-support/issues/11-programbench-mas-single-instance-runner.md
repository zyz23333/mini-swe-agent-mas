## What to build

Wire the single-instance ProgramBench runner end to end through MAS: provision the cleanroom Docker Action Environment Binding, create a Configured Interactive Root, submit a Root spawn command, wait for the Child result, close the submitted Child, export the workspace, and clean up.

## Acceptance criteria

- [x] The runner drives execution through a Configured Interactive Root Agent rather than constructing a regular `DefaultAgent`.
- [x] The runner submits a Root command such as `mini-mas spawn --wait "<task>"`.
- [x] Model calls remain in the host Runtime Process Environment.
- [x] Ordinary bash actions execute through the `docker/shared` Action Environment Binding.
- [x] A Child in `waiting_for_parent` with a submission is treated as ready for workspace export.
- [x] The runner closes the submitted Child through the Root authority path before or as part of finalization.
- [x] `execution_blocked`, `failed`, and `limits_exceeded` are recorded instead of being treated as valid submissions.
- [x] The runner exports `submission.tar.gz` in the ProgramBench eval format.
- [x] Default tests use deterministic models and mocked or tiny local Docker fixtures.
