## Acceptance criteria

- [x] Lock identity is derived from workspace/runtime namespace and Action Environment ID.
- [x] Lock files live under `.mini-mas/runtime/action-environment-locks/`.
- [x] The implementation uses a process-local lock for in-process concurrency.
- [x] The implementation uses a POSIX file lock for cross-process concurrency.
- [x] Same-binding bash actions are serialized by tests.
- [x] Different-binding actions use different locks and can proceed independently at the lock API level.
- [x] The lock is held only during one ordinary bash action.
- [x] The lock is not a TTL lease and does not use a DBOS dynamic queue.
- [x] Lock setup/acquisition failure maps to an execution-blocked style error.
