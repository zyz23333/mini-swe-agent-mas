# Retire run-first external CLI behavior for the new Root CLI surface

Status: done

## What to build

Complete the CLI surface transition from the previous `run`-first MAS interface to the Interactive Root Agent CLI model. The first-version external CLI should emphasize `mini-mas`, `spawn`, `status`, and `resume`, avoid naked external governance commands, and keep Root closure and cleanup out of scope.

## Acceptance criteria

- [x] CLI help and command descriptions present `mini-mas`, `spawn`, `status`, and `resume` as the first-version Root CLI surface.
- [x] The old `run`-first wording and root/run-scoped output are removed from the new primary CLI path.
- [x] Naked external `wait`, `continue`, and `close` are not introduced as supported bypasses around Interactive Root Agent context.
- [x] External `wait`, `continue`, and `close` are absent or rejected as unsupported external governance commands.
- [x] Workflow-layer `mini-mas wait`, `mini-mas continue`, and `mini-mas close` remain available inside an Agent as Standalone MAS Commands.
- [x] No `close-root`, Root cleanup, Root index, global root, or run ID behavior is added.
- [x] Help and error text do not suggest Root Agent closure, cleanup, `close-root`, a Root index, a global root, or run IDs.
- [x] Error messages direct users toward `mini-mas status` and `mini-mas resume <root-agent-id>` when they need to re-enter a Root Agent.
- [x] Tests cover the final command help and unsupported command boundaries.

> **Current behavior:**

The external CLI still exposes or documents command paths that make it look as if users can directly start a minimal Root Agent or directly wait, continue, or close Child Agents from outside an Agent.
