# Add Interactive Root Agent idle lifecycle and metadata banner

Status: ready-for-agent

## Parent

## What to build

Add the minimum Interactive Root Agent path: creating a parentless Root Agent, publishing `waiting_for_command` when idle, writing Root Agent artifacts, and printing Root Agent metadata before the prompt for plain `mini-mas`. This slice should make Root Agent creation observable without requiring the full command loop yet.

## Acceptance criteria

- [ ] `mini-mas` without a subcommand creates a parentless Interactive Root Agent.
- [ ] The new Root Agent publishes a `waiting_for_command` lifecycle state when idle.
- [ ] The Root Agent writes per-Agent metadata and a Trajectory Artifact using the Agent-scoped artifact layout.
- [ ] The CLI prints Root Agent metadata once before entering the command prompt.
- [ ] The printed metadata includes Root Agent ID, lifecycle state, Agent Artifact Directory, and Trajectory Artifact path.

## Agent Brief

**Category:** enhancement
**Summary:** Add the minimal Interactive Root Agent idle lifecycle and metadata banner for plain `mini-mas`.

**Current behavior:**
The External MAS CLI still exposes the earlier minimal Root Agent startup path through an explicit subcommand. Running plain `mini-mas` does not yet create an Interactive Root Agent. The Root Agent startup path can allocate opaque Agent IDs, start a parentless Root Agent workflow, write Agent-scoped artifact metadata, and persist a Trajectory Artifact, but the idle Interactive Root Agent state is not yet exposed as `waiting_for_command`.

Lifecycle status snapshots do not yet include `waiting_for_command`, so a newly created Interactive Root Agent cannot publish the specific idle state required for later resume behavior. The plain CLI entrypoint also does not yet print the Root Agent metadata banner before an interactive prompt.

**Desired behavior:**
Running plain `mini-mas` should create a new parentless Interactive Root Agent and make that creation observable before any full command loop exists. When the new Root Agent is idle and ready to receive future commands, it should publish lifecycle state `waiting_for_command`.

The Root Agent should write its per-Agent metadata and Trajectory Artifact using the Agent-scoped artifact layout introduced by the previous issue. The CLI should print the Root Agent metadata exactly once before entering the prompt path. The printed banner should include the Root Agent ID, lifecycle state, Agent Artifact Directory, and Trajectory Artifact path.

This slice may use a minimal prompt/idle path that proves the Root Agent was created and is waiting. It does not need to implement command execution through the prompt yet.

**Key interfaces:**
- Plain External MAS CLI invocation — `mini-mas` with no subcommand should become the minimal Interactive Root Agent entrypoint.
- Interactive Root Agent workflow startup — should create a parentless Root Agent with DBOS workflow ID equal to the Agent ID.
- Lifecycle status snapshots — should accept and publish `waiting_for_command` for idle Interactive Root Agents.
- Agent Metadata — should expose Root Agent ID, optional Parent Agent ID semantics, Agent Artifact Directory, and Trajectory Artifact path without adding `is_root`, `interaction_mode`, root index, run ID, or root-scoped artifact fields.
- Trajectory Artifact persistence — should write the Root Agent's trajectory under its own Agent Artifact Directory.
- CLI metadata rendering — should print the Root Agent metadata banner once before the prompt path.

**Acceptance criteria:**
- [ ] `mini-mas` without a subcommand creates one parentless Interactive Root Agent.
- [ ] The Root Agent's DBOS workflow ID equals its opaque Agent ID.
- [ ] The Root Agent publishes a lifecycle status snapshot with `lifecycle_state: waiting_for_command` when idle.
- [ ] `waiting_for_command` is treated as a valid lifecycle state for Interactive Root Agents.
- [ ] The Root Agent writes per-Agent metadata using Agent Metadata fields: Agent ID, Agent Artifact Directory, and Trajectory Artifact path.
- [ ] The Root Agent's Trajectory Artifact is written under its Agent Artifact Directory.
- [ ] The CLI prints the Root Agent metadata banner exactly once before entering the prompt path.
- [ ] The printed banner includes Root Agent ID, lifecycle state, Agent Artifact Directory, and Trajectory Artifact path.
- [ ] The implementation does not add `is_root`, `interaction_mode`, root index, global root, run ID, or root-scoped artifact paths.
- [ ] Tests cover the plain `mini-mas` entrypoint, the `waiting_for_command` lifecycle event, Root Agent artifact writing, and the metadata banner contents.

**Out of scope:**
- Implementing the full Interactive Root Agent command loop.
- Implementing Root Command Signals or Root Command Results.
- Implementing `mini-mas resume`.
- Implementing external `mini-mas status` discovery.
- Implementing one-shot external `mini-mas spawn`.
- Implementing concurrent terminal attachment checks.
- Implementing Root Agent close, delete, cleanup, garbage collection, or retention policy.
- Adding prefix-free prompt commands such as `status`.
