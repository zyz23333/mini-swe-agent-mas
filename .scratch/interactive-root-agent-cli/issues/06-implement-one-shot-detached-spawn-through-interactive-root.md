Implement external `mini-mas spawn "task"` as a one-shot command that creates an Interactive Root Agent, sends the first `mini-mas spawn "task"` command through that Root Agent, returns the spawned Child Agent metadata, and detaches while leaving the Root Agent available for later resume.

## Agent Brief

**Category:** enhancement
**Summary:** Implement external one-shot `mini-mas spawn ...` through a newly created Interactive Root Agent.

**Current behavior:**
The Interactive Root Agent foundation exists. The External MAS CLI can create an Interactive Root Agent, wait for its `waiting_for_command` lifecycle state, send a Root Command Signal, and wait for a command-id-scoped Root Command Result. External `resume` already sends terminal input through the Root command path, and workflow-layer `mini-mas spawn ...` already implements Detached Spawn and Waited Spawn behavior for Child Agents.

The blocker for this issue, `.scratch/interactive-root-agent-cli/issues/03-deliver-root-command-signals-and-results-end-to-end.md`, is now done. The remaining gap is the user-facing one-shot external `mini-mas spawn ...` convenience path. External spawn should no longer be treated as a naked external Agent Interaction, and the CLI must not directly create Child Agents outside the Root Agent's MAS Governance context.

**Desired behavior:**
When a user runs external `mini-mas spawn "task"` or external multi-spawn variants, the CLI should create one new Interactive Root Agent, wait until that Root Agent publishes `waiting_for_command`, then submit the user's external spawn invocation as one standalone `mini-mas spawn ...` command through a Root Command Signal.

The Root Agent should execute that command through the existing Root Command Signal/Result flow, so the spawned Agent or Agents are direct Child Agents of the new Root Agent. After the Root Command Result is received, the external CLI should render output focused on the spawned Child Agent metadata while also including the `root_agent_id` needed for later `mini-mas resume <root-agent-id>`.

The submitted command must preserve the external invocation as a standalone MAS Command. It should include the `mini-mas spawn` prefix and the user's spawn options and task arguments, rather than passing only parsed task strings or directly calling spawn helpers from the CLI process.

If waiting for the Root Command Result times out, the CLI should report that the command may still be running, include the `root_agent_id`, recommend `mini-mas status` and `mini-mas resume <root-agent-id>`, and leave the Root Agent and any Child Agents alone. A result timeout must not cancel children, close children, mark the Root Agent failed, or otherwise imply failed spawn recovery.

**Key interfaces:**
- External MAS CLI `spawn` command — should become a one-shot convenience command that creates an Interactive Root Agent and submits the first `mini-mas spawn ...` command through it.
- Interactive Root Agent startup result — should provide the new Root Agent ID and confirm `waiting_for_command` before the first Root Command Signal is sent.
- Root Command Signal — should carry the preserved standalone `mini-mas spawn ...` command, a command ID, the target `root_agent_id`, and external CLI source context.
- Root Command Result — should be the only source the external spawn path uses to learn what the Root Agent's workflow-layer spawn command returned.
- Existing MAS Agent command result shape — should continue to carry spawn output and metadata in `output`, `returncode`, `exception_info`, and `extra`.
- Child Agent metadata — the external one-shot spawn output should expose each spawned Child Agent ID, Parent Agent ID, Agent Artifact Directory, and Trajectory Artifact path.
- Root Agent metadata — `root_agent_id` should be included for later Resume, but Root Agent artifact paths should not be printed by default in the one-shot spawn output.

**Acceptance criteria:**
- [x] External `mini-mas spawn "task"` creates one new Interactive Root Agent.
- [x] External one-shot spawn waits for the new Root Agent to publish `waiting_for_command` before sending the first Root Command Signal.
- [x] The submitted Root Command Signal preserves the user's external spawn invocation as one standalone `mini-mas spawn ...` MAS Command.
- [x] The first spawn command is executed by the Root Agent through the Root Command Signal/Result flow.
- [x] The spawned Agent is a direct Child Agent of the new Root Agent.
- [x] External one-shot spawn output includes `root_agent_id` for later `mini-mas resume <root-agent-id>`.
- [x] External one-shot spawn output emphasizes spawned Child Agent metadata, including child Agent ID, Parent Agent ID, Agent Artifact Directory, and Trajectory Artifact path.
- [x] External one-shot spawn output does not show Root Agent artifact paths by default.
- [x] After one-shot spawn returns, the Root Agent remains available for Resume when it is `waiting_for_command`.
- [x] External multi-spawn creates one Interactive Root Agent and multiple direct Child Agents under that Root Agent.
- [x] External multi-spawn output includes one `root_agent_id` and one metadata entry per Child Agent.
- [x] Existing workflow-layer Detached Spawn and Waited Spawn semantics remain unchanged.
- [x] External `mini-mas spawn --timeout <seconds>` without `--wait` remains invalid because Detached Spawn has no wait phase.
- [x] If waiting for the Root Command Result times out, the CLI reports that the command may still be running, includes `root_agent_id`, recommends `mini-mas status` and `mini-mas resume <root-agent-id>`, and does not cancel children or mark the Root failed.
- [x] Tests cover CLI output, Root creation, waiting for `waiting_for_command`, Root Command Signal command preservation, direct Child Agent parentage, one-shot multi-spawn output, Root artifact omission, timeout messaging, and the invalid detached timeout case.

**Out of scope:**
- Implementing naked external `wait`, `continue`, or `close` commands.
- Changing External MAS CLI `status` discovery semantics.
- Changing `resume` terminal behavior beyond what is needed for one-shot spawn compatibility.
- Adding prefix-free prompt commands such as `status`.
- Adding Root Agent close, delete, cleanup, garbage collection, or retention policy.
- Supporting multiple simultaneous terminal attachments to one Interactive Root Agent.
- Introducing a Root Agent index, global Root Agent, `is_root` flag, interaction-mode flag, run ID, or Root-scoped artifact layout.
- Introducing a new Root Command Result payload schema.
- Solving exactly-once spawn recovery semantics or adding an Operation Ledger.
