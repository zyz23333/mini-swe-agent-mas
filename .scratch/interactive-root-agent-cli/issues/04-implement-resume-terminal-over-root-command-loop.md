## Agent Brief

**Category:** enhancement
**Summary:** Implement `mini-mas resume <root-agent-id>` as a terminal attachment to an existing Interactive Root Agent.

**Current behavior:**
The Interactive Root Agent command transport exists. The External MAS CLI can send a single bash-shaped command to an Interactive Root Agent through a Root Command Signal and wait for the matching Root Command Result. The Interactive Root Agent executes commands through the existing MAS-aware bash action flow, records observations in its Trajectory Artifact where possible, publishes Root Command Results scoped by command ID, and returns to `waiting_for_command` after recoverable command completion or error.

There is not yet a user-facing `mini-mas resume <root-agent-id>` terminal entrypoint that validates an existing Interactive Root Agent, prints its metadata once, accepts repeated user input, sends each line as a Root Command Signal, prints each Root Command Result, and detaches without closing the Root Agent when the terminal exits.

**Desired behavior:**
`mini-mas resume <root-agent-id>` should re-enter an existing Interactive Root Agent only when that Agent is currently `waiting_for_command`.

Before querying or attaching, resume should validate that the supplied Agent ID matches the opaque Agent ID shape. Resume should reject unknown Agent IDs, Child Agent IDs, and parentless workflows that are not Interactive Root Agent workflow types. Resume should also reject Interactive Root Agents whose latest lifecycle state is `running`, `waiting_for_child`, `failed`, `closed`, or `limits_exceeded`.

When resume is unavailable, the CLI output should clearly include the requested Root Agent ID and the relevant lifecycle state when one is known. The message should direct the user to `mini-mas status` and to retry `mini-mas resume <root-agent-id>` later when appropriate.

When resume succeeds, it should print the Root Agent metadata banner exactly once before accepting input. Each entered line should be submitted to the Root Agent as a Root Command Signal. The CLI should print the Root Command Result output for each submitted command and use the result return code consistently with existing CLI behavior.

Terminal input should preserve the established command rules: full standalone `mini-mas ...` commands are accepted, prefix-free MAS shorthand is not added, and ordinary bash commands are accepted and executed by the Root Agent. Ordinary bash actions and observations should remain recorded in the Root Agent Trajectory Artifact by the existing Root command path.

Exiting the local terminal should detach only. It must not close the Interactive Root Agent and must leave it available to return to `waiting_for_command`. The resume terminal must not create or reuse a prompt-history file.

**Key interfaces:**
- External MAS CLI `resume <root-agent-id>` command - new user-facing terminal entrypoint.
- Opaque Agent ID validation - resume must reject invalid Agent ID shape before DBOS query or attachment.
- Interactive Root Agent lookup/validation - must confirm the target workflow exists, has no parent Agent, and is the Interactive Root Agent workflow type/name.
- Root lifecycle status event - latest lifecycle state gates whether resume can attach.
- Root metadata banner - should render Agent ID, lifecycle state, Agent Artifact Directory, and Trajectory Artifact path once before input.
- Root Command Signal sending API - each accepted input line should use the existing command signal/result path rather than executing Root Agent actions in the CLI process.
- Root Command Result rendering - output and return code should be surfaced to the terminal using the existing MAS command result shape.
- Trajectory Artifact persistence - ordinary bash command actions and observations should continue to be persisted through the Root Agent command loop.
