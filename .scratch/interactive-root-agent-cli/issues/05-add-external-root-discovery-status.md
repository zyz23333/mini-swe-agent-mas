# Add external Root discovery with mini-mas status

Status: ready-for-agent

## Parent

.scratch/interactive-root-agent-cli/PRD.md
.scratch/interactive-root-agent-cli/DESIGN.md

## What to build

Implement external `mini-mas status` as a discovery view for Interactive Root Agents. It should list parentless Interactive Root Agent workflows and print Root Agent metadata and lifecycle state without entering MAS Governance or showing child details.

## Acceptance criteria

- [ ] `mini-mas status` lists parentless Interactive Root Agent workflows.
- [ ] Root discovery filters parentless workflows by Interactive Root Agent workflow type/name.
- [ ] Parentless non-Interactive workflows are not shown in external `mini-mas status`.
- [ ] Root discovery does not depend on a global root, Root Agent index, `is_root` flag, or interaction-mode flag.
- [ ] The output includes Root Agent ID, lifecycle state, Agent Artifact Directory, and Trajectory Artifact path.
- [ ] Failed or otherwise non-resumable Root Agents are still listed with their lifecycle state.
- [ ] The output does not include Child Agent counts, Child Agent status, latest commands, or history summaries.
- [ ] Workflow-layer `mini-mas status` inside an Agent remains the direct-child status command and is not conflated with external discovery.
- [ ] DBOS query or configuration errors fail visibly and preserve the underlying error instead of returning an empty status list.

> **Category:** enhancement
> **Summary:** Implement external `mini-mas status` as Interactive Root Agent discovery.

> **Current behavior:**
> External `mini-mas status` is still shaped like the earlier naked Agent Interaction path. It requires an Agent ID argument and returns an unsupported external coordination response instead of listing Interactive Root Agents. Workflow-layer `mini-mas status` inside an Agent already exists as the Direct Child Agent status command and should remain scoped to the current Parent Agent's direct Child Agents.
>
> The prerequisite Interactive Root Agent slice is complete: parentless Interactive Root Agents can be started, publish `waiting_for_command`, and expose Agent Metadata fields for Agent ID, Agent Artifact Directory, and Trajectory Artifact path.
>
> **Desired behavior:**
> Running external `mini-mas status` without an Agent ID should act as a discovery view for Interactive Root Agents. It should query DBOS workflow metadata for parentless workflows, filter those workflows to the Interactive Root Agent workflow type/name, read each Root Agent's latest lifecycle snapshot, and print one Root Agent entry per discovered Interactive Root Agent.
>
> The discovery view should include Root Agent ID, lifecycle state, Agent Artifact Directory, and Trajectory Artifact path. It should list failed, closed, running, waiting-for-child, waiting-for-command, and otherwise non-resumable Interactive Root Agents when they match the parentless Interactive Root Agent workflow criteria.
>
> DBOS configuration errors, workflow query errors, and status event read errors should fail visibly and preserve the underlying error. They must not be converted into an empty discovery result.
>
> **Key interfaces:**
> - External `mini-mas status` CLI command - should become a no-target Root discovery command.
> - DBOS workflow listing/query API - should be used to discover parentless workflow records.
> - Interactive Root Agent workflow identity - should be identified by workflow type/name plus no parent workflow, not by Agent Metadata flags.
> - Root Agent lifecycle status snapshot - should supply lifecycle state and Agent Metadata for the external status output.
> - Workflow-layer `mini-mas status [agent-id]` command - should remain the Direct Child Agent status command inside an Agent context.
>
