# Map one-shot waited spawn options to existing MAS wait semantics

Status: done

## What to build

Support `--wait`, `--all`, and `--timeout` on external one-shot `mini-mas spawn` by routing them through the Interactive Root Agent to the existing workflow-layer Waited Spawn behavior. The command should wait for First Observable Events, not final workflow results, and keep spawned children running on timeout.

## Acceptance criteria

- [x] `mini-mas spawn --wait "task"` waits for a First Observable Event using wait-any behavior.
- [x] `mini-mas spawn --wait --all "task A" "task B"` waits until all started children become observable or timeout.
- [x] `mini-mas spawn --wait --timeout <seconds> "task"` bounds only the wait phase.
- [x] Timeout returns available ready child data and still-running child IDs without cancelling, closing, failing, or retrying children.
- [x] Waited spawn output follows the existing MAS waited result shape, including wait mode, timed-out indication, ready child snapshots, and still-running child IDs where applicable.
- [x] The external CLI wait timeout is distinct from `mini-mas spawn --wait --timeout <seconds>`, which only bounds the MAS Waited Spawn wait phase.
- [x] `mini-mas spawn --timeout <seconds> "task"` without `--wait` remains invalid.
- [x] The Interactive Root Agent is `waiting_for_child` during the waited phase and returns to `waiting_for_command` after the one-shot command detaches.

## Agent Brief

**Category:** enhancement
**Summary:** Map external one-shot `mini-mas spawn --wait` options through the Interactive Root Agent to existing Waited Spawn semantics.

**Current behavior:**
External one-shot `mini-mas spawn ...` already creates an Interactive Root Agent, preserves the external invocation as a standalone `mini-mas spawn ...` command, sends it through the Root Command Signal/Result flow, and prints the Root Agent ID plus spawned Child Agent metadata.

Workflow-layer `mini-mas spawn --wait` already implements Waited Spawn behavior for Child Agents. It waits for First Observable Events rather than final workflow results, supports wait-any and wait-all modes, supports timeout-bounded waits, and does not cancel or fail children on timeout.

The remaining gap is to make the external one-shot boundary explicitly support and test `--wait`, `--all`, and MAS wait-phase `--timeout` when these options are passed through `mini-mas spawn ...`.

**Desired behavior:**
When a user runs external `mini-mas spawn --wait "task"`, the External MAS CLI should create an Interactive Root Agent, submit a standalone Root command equivalent to the user's invocation, and return the existing MAS waited spawn result shape from the Root Command Result. The wait should use First Observable Events and default to wait-any behavior.

When a user runs external `mini-mas spawn --wait --all "task A" "task B"`, the command should wait until all started children become observable or until the MAS wait-phase timeout is reached.

When a user runs external `mini-mas spawn --wait --timeout <seconds> "task"`, the `--timeout` option should be part of the submitted MAS spawn command and should bound only the Waited Spawn wait phase. This timeout is distinct from the external CLI Root Command Result timeout option.

If the MAS wait phase times out, the command should return available ready child snapshots and still-running child IDs using the existing waited result shape. Timeout must not cancel, close, fail, retry, or otherwise mutate still-running Child Agents.

External `mini-mas spawn --timeout <seconds> "task"` without `--wait` should remain invalid because Detached Spawn has no wait phase.

During the waited phase, the Interactive Root Agent should publish `waiting_for_child`, then return to `waiting_for_command` after the one-shot command completes and detaches.

**Key interfaces:**
- External `mini-mas spawn ...` CLI command - should preserve `--wait`, `--all`, and MAS `--timeout` options in the standalone Root command it submits.
- Root Command Signal and Root Command Result - one-shot waited spawn must continue to enter MAS governance through the Interactive Root Agent, not by direct external child control.
- Workflow-layer `mini-mas spawn` command parsing - should continue to reject `--timeout` without `--wait` and preserve existing Waited Spawn semantics.
- Existing MAS command result shape - waited one-shot output should expose wait mode, timed-out indication, ready child snapshots, ready child IDs where applicable, child metadata, and still-running child IDs.
- External CLI timeout option - the Root Command Result wait timeout should remain separate from MAS `spawn --wait --timeout`.

**Acceptance criteria:**
- [x] External `mini-mas spawn --wait "task"` submits a standalone `mini-mas spawn --wait "task"` command through an Interactive Root Agent.
- [x] External `mini-mas spawn --wait "task"` waits for a First Observable Event using wait-any behavior, not final workflow completion.
- [x] External `mini-mas spawn --wait --all "task A" "task B"` waits until all started children become observable or the MAS wait-phase timeout is reached.
- [x] External `mini-mas spawn --wait --timeout <seconds> "task"` passes the timeout into workflow-layer Waited Spawn and bounds only the Waited Spawn wait phase.
- [x] MAS wait-phase timeout returns available ready child data and still-running child IDs without cancelling, closing, failing, or retrying children.
- [x] One-shot waited spawn output follows the existing MAS waited result shape, including wait mode, timed-out indication, ready child snapshots, and still-running child IDs where applicable.
- [x] The external Root Command Result timeout remains distinct from MAS `spawn --wait --timeout`; tests cover both timeout paths so they cannot be confused.
- [x] External `mini-mas spawn --timeout <seconds> "task"` without `--wait` remains invalid.
- [x] The Interactive Root Agent publishes `waiting_for_child` during the waited phase and is available as `waiting_for_command` after the one-shot command completes and detaches.
- [x] Existing detached one-shot spawn and one-shot multi-spawn result ordering behavior remain unchanged.

**Out of scope:**
- Adding naked external `mini-mas wait`, `continue`, or `close` governance commands.
- Changing workflow-layer Waited Spawn semantics beyond what is required to expose them through one-shot external spawn.
- Introducing a new Root Command Result payload schema.
- Cancelling, closing, failing, or retrying Child Agents on Waited Spawn timeout.
- Solving exactly-once spawn recovery or adding an Operation Ledger.
- Changing Direct Child Authority Policy.
- Adding Root Agent close, cleanup, or retention behavior.
