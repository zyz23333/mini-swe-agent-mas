# Harden Root CLI error and timeout boundaries

Status: ready-for-agent

## Parent

## What to build

Harden the first-version Interactive Root Agent CLI error paths so CLI input errors, Root unavailable states, Root Command Result wait timeouts, command execution errors, and DBOS query failures match the design. This issue should not add new MAS governance commands, Root cleanup behavior, a Root index, or a global root.

## Acceptance criteria

- [ ] Invalid external CLI arguments fail before starting workflows where possible.
- [ ] `mini-mas spawn --timeout <seconds> "task"` without `--wait` returns a usage error and does not start a Root Agent.
- [ ] `mini-mas resume not-an-agent-id` returns a usage error and does not attach.
- [ ] `mini-mas resume <child-agent-id>` clearly reports that the target is not an Interactive Root Agent.
- [ ] Resume unavailable errors include Agent ID and lifecycle state and recommend `mini-mas status` plus retrying `mini-mas resume <root-agent-id>` later.
- [ ] Root Command Result wait timeout reports that the command may still be running, includes `root_agent_id`, recommends status/resume, and does not cancel children.
- [ ] CLI-side Root Command Result wait timeout does not mark the Root Agent failed.
- [ ] Recoverable Root command execution failures publish non-zero Root Command Results and do not kill the Root command loop.
- [ ] DBOS query or configuration errors fail visibly and preserve the underlying exception message.
- [ ] Error and help text do not suggest `close-root`, Root cleanup, a global root, a Root index, or run IDs.

## Agent Brief

**Category:** enhancement
**Summary:** Harden Interactive Root Agent CLI error and timeout boundaries.

**Current behavior:**
The Interactive Root Agent CLI redesign is mostly implemented: External MAS CLI commands can create Interactive Root Agents, submit one-shot spawn commands through Root Command Signals, wait for command-id-scoped Root Command Results, discover parentless Interactive Root Agents, resume waiting Roots, and enforce a single active Root attachment.

Several error and timeout boundaries still need a focused hardening pass. Some validation happens only after a Root Agent has already been started, some timeout messages are too generic, and the CLI should consistently preserve DBOS/configuration failures while avoiding first-version out-of-scope concepts in user-facing text.

**Desired behavior:**
Invalid external CLI input should fail at the CLI boundary before workflows are started whenever the invalidity can be determined from arguments alone. In particular, external `mini-mas spawn --timeout <seconds> "task"` without `--wait` should return a usage error and must not create an Interactive Root Agent.

`mini-mas resume` should continue to reject invalid Agent ID shapes before querying DBOS. It should clearly reject Child Agent IDs and parentless non-Interactive workflows as targets that are not Interactive Root Agents. Root unavailable errors should include the requested Agent ID, the lifecycle state when known, and should direct users to `mini-mas status` and retrying `mini-mas resume <root-agent-id>` later.

Root Command Result wait timeouts should be reported as an external wait timeout, not as proof that the Root command failed. Timeout output should say that the command may still be running, include `root_agent_id`, recommend `mini-mas status` and `mini-mas resume <root-agent-id>`, and must not cancel children or mark the Root Agent failed from the CLI side.

Recoverable Root command execution failures should publish a non-zero Root Command Result and leave the Root command loop alive. DBOS query, DBOS configuration, and Root discovery/resume errors should fail visibly while preserving the underlying exception message instead of being converted into empty or misleading success output.

User-facing error and help text must stay within the first-version Interactive Root Agent CLI scope. It should not suggest `close-root`, Root cleanup, a global root, a Root index, or run IDs.

**Key interfaces:**
- External `mini-mas spawn` CLI command - should validate argument combinations that are externally knowable before starting an Interactive Root Agent.
- External `mini-mas resume <root-agent-id>` CLI command - should preserve Agent ID validation, Interactive Root Agent validation, lifecycle gating, and clear unavailable errors.
- Root Command Signal submission and Root Command Result waiting API - should distinguish command-result wait timeout from MAS command timeout and from command execution failure.
- Existing MAS command result shape - should remain the payload contract for successful commands, usage errors, recoverable command execution failures, and waited spawn timeout results.
- Interactive Root Agent lifecycle status - should not be changed to `failed` by CLI-side Root Command Result wait timeout.
- External Root discovery/status path - should continue to surface DBOS query/configuration failures visibly.
- CLI help and unsupported-command messages - should describe only the first-version `mini-mas`, `spawn`, `status`, and `resume` surface.

**Acceptance criteria:**
- [ ] Invalid external CLI arguments fail before starting workflows where the CLI can determine invalidity without DBOS state.
- [ ] `mini-mas spawn --timeout <seconds> "task"` without `--wait` returns a usage error and does not start an Interactive Root Agent.
- [ ] `mini-mas resume not-an-agent-id` returns a usage error and does not query or attach through DBOS.
- [ ] `mini-mas resume <child-agent-id>` clearly reports that the target is not an Interactive Root Agent.
- [ ] Resume unavailable errors include the requested Agent ID and lifecycle state when known.
- [ ] Resume unavailable errors recommend `mini-mas status` and retrying `mini-mas resume <root-agent-id>` later.
- [ ] Root Command Result wait timeout output says the command may still be running.
- [ ] Root Command Result wait timeout output includes `root_agent_id`.
- [ ] Root Command Result wait timeout output recommends `mini-mas status` and `mini-mas resume <root-agent-id>`.
- [ ] CLI-side Root Command Result wait timeout does not cancel, close, fail, or retry Child Agents.
- [ ] CLI-side Root Command Result wait timeout does not mark the Root Agent failed.
- [ ] Recoverable Root command execution failures publish non-zero Root Command Results.
- [ ] Recoverable Root command execution failures do not kill the Root command loop.
- [ ] DBOS query or configuration errors fail visibly and preserve the underlying exception message.
- [ ] Error and help text do not suggest `close-root`, Root cleanup, a global root, a Root index, or run IDs.
- [ ] Tests cover the CLI boundary behavior, Root Command Result timeout behavior, resume rejection paths, DBOS error propagation, and forbidden help/error text.

**Out of scope:**
- Adding new MAS governance commands.
- Adding naked external `wait`, `continue`, or `close`.
- Adding `close-root`, Root cleanup, deletion, retention, or garbage collection behavior.
- Adding a global root, Root index, `is_root` flag, interaction-mode flag, or run ID.
- Changing the Root Command Result payload schema beyond reusing the existing MAS command result shape.
- Changing Direct Child Authority or granting Root Agents tree-wide authority.
- Implementing spawn recovery or exactly-once child creation semantics.
